أريد منك بناء مشروع ويب كامل واحترافي لإدارة وعرض **البرنامج الأسبوعي لكلية المعلوماتية**، بحيث يكون المشروع جاهزًا للنشر على **Vercel**، ويعمل بالكامل باستخدام:

* HTML
* CSS
* JavaScript

إذا احتاج المشروع إلى Backend أو قاعدة بيانات، استخدم الحل الأبسط والأكثر ملاءمة للنشر على Vercel، ويفضل استخدام **Supabase** كقاعدة بيانات وخدمة Backend إذا كان ذلك ضروريًا.

## 1. فكرة المشروع

المشروع عبارة عن نظام لإدارة وعرض **البرنامج الأسبوعي للمحاضرات في كلية المعلوماتية**.

يوجد نوعان من المستخدمين:

### الطالب

يدخل إلى الموقع ويستطيع مشاهدة البرنامج الدراسي، مع إمكانية الفلترة حسب:

1. السنة الدراسية
2. الجنس:

   * ذكور
   * إناث
3. الفئة / الشعبة / المجموعة

بعد اختيار الفلاتر، يظهر للطالب جدول البرنامج الخاص بالاختيارات التي حددها.

### الأدمن

يوجد قسم خاص بالأدمن يستطيع من خلاله:

* إضافة محاضرة
* تعديل محاضرة
* حذف محاضرة
* إنشاء وتعديل وحذف المواد
* إنشاء وتعديل وحذف المدرسين
* إنشاء وتعديل وحذف القاعات
* إدارة السنوات الدراسية
* إدارة الفئات / الشعب
* تحديد أوقات المحاضرات الخمس
* إدارة البرنامج الأسبوعي بالكامل

# 2. اللغة واتجاه الموقع

الموقع بالكامل باللغة العربية.

استخدم:

```text
dir="rtl"
```

ويجب أن يكون التصميم مناسبًا للغة العربية بشكل كامل.

استخدم الخط الموجود بمجلد المشروع خط قمرة

ويجب أن يكون التصميم Responsive ويعمل بشكل ممتاز على:

* الكمبيوتر
* اللابتوب
* التابلت
* الهاتف

# 3. أيام الأسبوع

الأسبوع الدراسي يتكون من 7 أيام، بالترتيب التالي:

1. الجمعة
2. السبت
3. الأحد
4. الاثنين
5. الثلاثاء
6. الأربعاء
7. الخميس

مهم جدًا:

**يجب أن تظهر الأيام في العمود الموجود على اليسار في الجدول، وليس في الصف العلوي.**

أي أن شكل الجدول يكون تقريبًا:

| اليوم    | المحاضرة الأولى | المحاضرة الثانية | المحاضرة الثالثة | المحاضرة الرابعة | المحاضرة الخامسة |

# 4. المحاضرات

كل يوم يحتوي على **5 محاضرات**.

الأدمن يستطيع تحديد وقت كل محاضرة من لوحة التحكم.

مثال:

* المحاضرة الأولى: 08:00 - 09:30
* المحاضرة الثانية: 09:45 - 11:15
* المحاضرة الثالثة: 11:30 - 13:00
* المحاضرة الرابعة: 13:15 - 14:45
* المحاضرة الخامسة: 15:00 - 16:30

لكن لا تجعل هذه الأوقات ثابتة داخل الكود.

الأدمن يستطيع تعديل أوقات المحاضرات من لوحة التحكم، وعند تعديل الوقت يتغير تلقائيًا في جميع أماكن الموقع.

---

# 5. محتوى كل خانة في الجدول

كل محاضرة يجب أن تعرض داخل الخانة:

**اسم المادة**

**اسم المدرس**

**القاعة**

مثال:

```text
برمجة ويب
د. أحمد محمد
قاعة 203
```

ويفضل تصميم الخانة بشكل Card صغير ومرتب.

مثلاً:

```text
┌──────────────────────┐
│     برمجة ويب        │
│                      │
│     د. أحمد محمد     │
│     قاعة 203         │
└──────────────────────┘
```

# 6. الفلاتر الخاصة بالطلاب

في أعلى صفحة البرنامج ضع قسمًا واضحًا للفلاتر.

يحتوي على:

### السنة الدراسية

Dropdown:

```text
اختر السنة
السنة الأولى
السنة الثانية
السنة الثالثة
السنة الرابعة
```

ويجب أن يكون الأدمن قادرًا على إضافة سنوات أخرى من لوحة التحكم.

### الجنس

Dropdown:

```text
الجنس
الكل
ذكور
إناث
```

### الفئة / الشعبة

Dropdown:

```text
الفئة
الكل
A
B
C
...
```

ويجب أن تكون هذه الفئات قابلة للإدارة من لوحة الأدمن.

بعد اختيار الفلاتر يتم عرض البرنامج المناسب مباشرة.

يمكن أن يكون هناك زر:

**عرض البرنامج**

لكن الأفضل أن يتم تحديث الجدول تلقائيًا بمجرد تغيير الفلاتر.

# 7. الصفحة الرئيسية للطالب

أنشئ Landing Page بسيطة واحترافية.

في الأعلى:

**كلية المعلوماتية**

وتحتها:

**البرنامج الدراسي الأسبوعي**

ثم الفلاتر.

ثم جدول المحاضرات.

اجعل التصميم عصريًا وأكاديميًا، وليس مجرد جدول HTML عادي.

---

# 8. شكل الجدول

أريد جدولًا واضحًا جدًا وسهل القراءة.

الأيام تكون في العمود الأيسر.

الصف العلوي يحتوي:

```text
المحاضرة الأولى
08:00 - 09:30

المحاضرة الثانية
09:45 - 11:15

المحاضرة الثالثة
11:30 - 13:00

المحاضرة الرابعة
13:15 - 14:45

المحاضرة الخامسة
15:00 - 16:30
```

لكن الأوقات يتم جلبها من إعدادات الأدمن.

اجعل رؤوس الجدول Sticky إن أمكن أثناء التمرير.

على الهاتف يجب ألا ينكسر الجدول.

يمكن استخدام horizontal scrolling للجدول على الشاشات الصغيرة.

# 9. لوحة تحكم الأدمن

أنشئ صفحة منفصلة مثل:

```text
/admin
```

ويجب أن تكون محمية بتسجيل دخول.

لا يجب أن يستطيع أي شخص الوصول إلى لوحة التحكم بدون تسجيل الدخول.

# 10. تسجيل دخول الأدمن

أنشئ Login Page للأدمن تحتوي على:

* البريد الإلكتروني أو اسم المستخدم
* كلمة المرور
* زر تسجيل الدخول

بعد تسجيل الدخول ينتقل إلى:

```text
/admin/dashboard
```

ويجب وجود زر:

**تسجيل الخروج**

مهم جدًا:

لا تضع كلمة مرور الأدمن بشكل مكشوف داخل JavaScript Frontend.

إذا تم استخدام Supabase، استخدم Supabase Auth.


# 13. تعديل وحذف المحاضرات

في جدول إدارة البرنامج يجب أن تظهر جميع المحاضرات.

الأعمدة:

```text
اليوم
المحاضرة
السنة
الجنس
الفئة
المادة
المدرس
القاعة
الإجراءات
```

الإجراءات:

```text
تعديل
حذف
```

عند الضغط على تعديل، يظهر Modal أو صفحة تعديل.

عند الحذف يجب إظهار Confirmation Dialog:

```text
هل أنت متأكد من حذف هذه المحاضرة؟
إلغاء
حذف
```

---

# 14. منع تعارض المحاضرات

أضف Validation ذكي.

مثلاً لا يسمح بإضافة محاضرتين لنفس:

* السنة
* الجنس
* الفئة
* اليوم
* المحاضرة

في نفس الوقت.

إذا حاول الأدمن ذلك، تظهر رسالة:

```text
يوجد محاضرة أخرى في هذا الوقت لهذه الفئة.
يرجى اختيار وقت آخر.
```

ويفضل أيضًا اكتشاف تعارض المدرس:

إذا كان المدرس لديه محاضرة في نفس اليوم ونفس الفترة لفئة أخرى، أظهر تحذيرًا.

وكذلك القاعة.

مثلاً:

```text
تنبيه:
القاعة 203 مستخدمة في محاضرة أخرى في نفس الوقت.
```

# 21. قاعدة البيانات

إذا احتاج المشروع إلى قاعدة بيانات، صمم Database Schema نظيفًا.

يفضل استخدام Supabase.

الجداول المقترحة:

```text
admins / auth.users
academic_years
categories
subjects
teachers
rooms
lecture_times
schedule
```

جدول schedule يجب أن يحتوي على علاقات مناسبة مع:

```text
academic_year
category
subject
teacher
room
day
lecture_period
gender
```

لا تكرر أسماء المواد والمدرسين والقاعات داخل كل سجل إذا كان من الأفضل استخدام Foreign Keys.

# 22. البيانات الديناميكية

مهم جدًا:

لا تضع البرنامج الدراسي داخل JavaScript بشكل ثابت.

كل البيانات يجب أن تكون Dynamic.

أي أن الأدمن إذا أضاف:

```text
مادة جديدة
```

تظهر مباشرة في قائمة المواد.

وإذا أضاف:

```text
مدرس جديد
```

يظهر مباشرة في Dropdown المدرسين.

وإذا أضاف:

```text
قاعة جديدة
```

تظهر مباشرة في Dropdown القاعات.

# 25. Empty States

إذا لم توجد محاضرات حسب الفلاتر، لا تترك الجدول فارغًا فقط.

```text
لا توجد محاضرات مسجلة لهذه الخيارات.
```

# 26. Loading States

أثناء تحميل البيانات من قاعدة البيانات، اعرض:

* Skeleton Loading
  أو
* Spinner

# 27. Error Handling

أضف معالجة أخطاء جيدة.

إذا حدث خطأ في قاعدة البيانات، اعرض رسالة مفهومة بالعربية.

مثلاً:

```text
حدث خطأ أثناء تحميل البرنامج.
يرجى المحاولة مرة أخرى.
```

ولا تعرض أخطاء JavaScript التقنية للمستخدم النهائي.

# 31. صفحة البرنامج للطالب

أريد إمكانية مشاركة رابط يحتوي على الفلاتر.

مثلاً إذا اختار المستخدم:


```text
/schedule?year=2&gender=male&category=A
```

وعند مشاركة الرابط وفتحه من طالب آخر، تظهر نفس الفلاتر والبرنامج مباشرة.

# 34. الأمان

اهتم بالأمان.

خصوصًا:

* حماية لوحة الأدمن
* عدم كشف بيانات الدخول
* عدم وضع Secret Keys في Frontend
* استخدام Environment Variables
* حماية عمليات الكتابة والحذف في قاعدة البيانات
* استخدام Row Level Security إذا تم استخدام Supabase

مهم جدًا:

أي API Key أو Secret يجب ألا يكون موجودًا في GitHub أو Frontend إذا كان Secret.

# 35. Vercel

المشروع يجب أن يكون جاهزًا للنشر على Vercel.

أنشئ جميع الملفات المطلوبة.

مثلاً إذا اخترت Vanilla HTML/CSS/JS:

```text
index.html
admin.html
css/
js/
assets/
```

وإذا اخترت Framework، استخدم Framework مناسب ومتوافق مع Vercel.

يجب أن تعطيني في النهاية:

1. هيكل المشروع.
2. جميع الملفات المطلوبة.
3. تعليمات تشغيل المشروع محليًا.
4. تعليمات ربط قاعدة البيانات.
5. تعليمات إنشاء حساب الأدمن.
6. Environment Variables المطلوبة.
7. تعليمات رفع المشروع على GitHub.
8. تعليمات نشره على Vercel.

# 37. مهم جدًا: لا تبنِ مجرد Prototype

لا أريد صفحة شكلية أو Mockup فقط.

أريد تطبيقًا فعليًا يعمل.

أي زر:

```text
إضافة
تعديل
حذف
حفظ
تسجيل الدخول
تسجيل الخروج
فلترة
بحث
```

يجب أن يعمل فعليًا.

إذا اخترت Supabase، اربط العمليات فعليًا بقاعدة البيانات.

---

# 38. تجربة المستخدم

أريد أن يكون استخدام الموقع بسيطًا جدًا.

الطالب لا يحتاج إلى تسجيل حساب.

يفتح الموقع ويجد:

```text
كلية المعلوماتية

البرنامج الدراسي

[ السنة ▼ ]
[ الجنس ▼ ]
[ الفئة ▼ ]

        عرض البرنامج

---------------------------------------

      جدول المحاضرات
```

ثم الجدول.

---

# 39. Responsive Mobile Design

على الهاتف، يجب أن يكون الجدول قابلًا للتمرير أفقيًا.

لا تصغر النصوص إلى درجة يصعب قراءتها.

يمكن أن يكون:

```text
← اسحب لرؤية بقية الجدول →
```

أو استخدام Scrollbar واضح.

# 40. جودة الكود

اكتب Code نظيف ومنظم.

افصل:

* UI
* Database
* Authentication
* API
* Utilities
* Components

ولا تضع كل JavaScript في ملف ضخم واحد إذا كان يمكن تقسيمه.

أضف تعليقات للكود في الأماكن المهمة.

استخدم أسماء Variables وFunctions واضحة.
